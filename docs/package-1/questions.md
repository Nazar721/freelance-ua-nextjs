## C. Мовна система і URL [Т/В]

| # | Питання | Пропозиція |
|---|---|---|
| C1 | Cookie `NEXT_LOCALE`: зараз змінює мову того самого URL. У новій системі мову визначає URL. Залишити cookie як допоміжну перевагу (напр. для майбутніх редіректів «нова адреса») чи прибрати її вплив повністю? | Прибрати вплив на вміст; cookie можна лишити для збереження вибору мови в перемикачі |
| C2 | Автоматичні редіректи за IP/мовою браузера — підтверджено: не виконувати. Чи потрібен хоча б один вхідний редірект (напр. старі `/uk/…`)? | `/uk/` для кейсів не вводити; поточний `/uk/` → 308 на `/uk` → 404 (лишити 404) |
| C3 | `x-default` у hreflang: яку політику встановити? Варіанти: `x-default = uk` (рідна мова), `x-default = /` як мовний вибір, або без x-default | Потрібне явне рішення перед Package 2 |
| C4 | Перемикач мови: посилання на відповідник зі збереженням фільтрів/fragment. Якщо відповідника немає — зафіксувати відсутність і погодити поведінку (пропозиція: показувати disabled-стан або вести на відповідник горівничої категорії, але не мовчки на головну) | Потрібне рішення власника |
| C5 | EN-версія `/en` для **всіх** 100 кейсів — обсяг перекладу вже наявний (2503 EN-ключі), але 39 кейс-сторінок мають 131 хардкод UA-рядок. Підтвердити: весь обсяг перекладається до фінального релізу | |
