## 2. Схема даних

`data/case-records/` — одне джерело правди для **детальної сторінки** кейсу:

| Файл | Призначення |
|---|---|
| `types.ts` | типи `CaseRecord`, дискриміновані секції та медіаблоки, `CaseText` |
| `index.ts` | реєстр (`caseRecords`), пошук за `direction/slug`, збір медіа, вибір «схожих робіт», EN-адреси для sitemap |
| `it/eva-code.ts`, `design/nastya-portrait-retouch.ts`, `video/cuprus-life.ts` | по одному файлу на перероблений кейс |

Ключові рішення моделі:

- **Первинний ключ — `direction/slug`** (`id`), не сам slug.
- **`CaseText`** — текст або у словнику (`{ key: "itCases…" }`), або
  літерал `{ uk, en }`. Ніякого третього варіанта: EN-сторінка фізично не
  може отримати український текст випадково. Наявні переклади використовуються
  як ключі (без дублювання), нові редакційні тексти — літерали.
- **Секції — дискримінований union**: `brief`, `featureList`, `compare`,
  `gallery`, `videoGrid`, `results`, `prose`, `links`. Порожня секція не
  рендериться; шаблонних «заглушок» у записах немає.
  `prose` (контекст / внесок агенції окремим абзацом) і `links` поки не
  використовуються жодним із трьох записів: у цих кейсах «внесок агенції»
  вже є в тексті «Рішення» («Ми розробили…» / «Змонтували…»), а дублювати
  його окремим блоком — той самий шаблонний блок, що заборонено ТЗ.
  Типи підтримуються рендерером і знадобляться для кейсів, де контекст
  чи внесок партнерів описані окремо (напр. спільні проєкти
  selloflow / importera / hope-media-group — п.5 правил редактури).
- **Медіа** — `image` / `imageGrid` / `video` (інтерактивна плитка з
  позначками, відкриває спільний плеєр) / `videoGrid` у hero, `gallery`,
  `compare` (slider і статична пара), `videoGrid` у тілі, `review`
  (`video` | `screenshot` | `text`). Порядок у масиві = порядок на сторінці.
  `MediaImage.presentation` — явна презентація з оригіналу: `splitMobile`
  (desktop цілий макет / mobile дві частини) і `maxWidth` для портретів;
  файл у даних не дублюється, повне зображення лишається в лайтбоксі.
- **Запис також годує**: метадані (title/description/canonical/OG/Twitter),
  видимий breadcrumb і його JSON-LD, EN-адреси в sitemap, список мовних пар.

Що **залишилося поза записом** (навмисно): тексти карток каталогу —
вони й надалі з `lib/i18n.ts` через `titleKey`/`descriptionKey` у
`data/{it,design,video}Cases.ts`. Каталог, головна й сторінки напрямів не
змінювалися.

### Чому тонкі статичні сторінки, а не динамічний маршрут

Кожен перероблений кейс має по маленькому `page.tsx` в обох деревах
(стара UA-адреса не змінюється, EN-сторінка створюється поруч), які лише
викликають `caseMetadata(id, locale)` і `<CasePage id locale />`.
Так:

- адреси, каталог і інструменти перевірки лишаються без змін;
- невідомий slug дає **справжній 404** (запису немає → `notFound()`);
- масове перенесення = новий файл запису + переписати тонкий `page.tsx` +
  створити EN-сторінку; жодного дублювання розмітки.

## 3. Спільні компоненти

| Компонент | Роль |
|---|---|
| `components/cases/CasePage.tsx` | серверна оболонка: дістає запис і «схожі роботи», віддає рендереру |
| `components/cases/CaseDetail.tsx` | рендер усього каркаса: breadcrumb → назад → hero → секції → відгук → команда → наступний крок → схожі роботи → модалка галереї |
| `components/cases/CaseHero.tsx` | eyebrow (+піл формату), H1, lead, рамка з scroll-анімацією; варіанти `image` / `imageGrid` / `videoGrid` |
| `components/cases/CaseMedia.tsx` | `CaseFeatureList`, `CaseCompare`, `CaseGallery`, `CaseVideoGrid`, `VideoTiles`, `FullscreenVideo` |
| `components/cases/CaseBreadcrumbs.tsx` | видимий ланцюжок «Головна → напрям → кейс» |
| `components/cases/RelatedCases.tsx` | 3 картки схожих робіт з реєстру, без поточного кейсу |
| `lib/case-page.ts` | `caseMetadata()` — метадані через `localizedMetadata()` (self-canonical, reciprocal hreflang, OG/Twitter) |
| `lib/case-breadcrumbs.ts` | **спільне джерело ланцюжка** для розмітки й JSON-LD `BreadcrumbList` |

Перевикористано наявні UI-компоненти без зміни їхньої поведінки:
`FadeIn`, `CurvedDashedLines`, `GalleryImage`, `ImageModal`,
`BeforeAfterSlider`, `ReviewAvatar`, `Image`/`Link` з Next.
`GalleryImage` і `ImageModal` отримали **опціональні** пропи локалізованих
aria-label (без пропів — стара англійська мова, тож 97 невербованих сторінок
не змінилися).

Доступність нових блоків: плитка відео — це справжня `<button type="button">`
з локалізованим `aria-label` (раніше в оригінальній сторінці був `<div>` з
`onClick`, недоступний з клавіатури); повноекранний плеєр закривається
**Escape** і повертає фокус на плитку — той самий контракт, що й у
наявної `ImageModal`. alt зображень і підписи локалізовані.

Мова: серверна оболонка знає `locale` з дерева маршрутів
(`app/(uk)/` vs `app/en/`), рендерер бере словник із наявного
`LanguageProvider` — два root-layout дерева з Пакета 2 не змінювалися.

## 5. Чому саме ці три кейси

Вибір — за різноманітністю блоків, а не за «силою» роботи.

| Кейс | Які типи блоків покриває | Чому це важливо |
|---|---|---|
| **`it/eva-code`** | hero-зображення, brief (task+solution), `featureList` ×5 (з двома зовнішніми лінками, з 4 групами скріншотів, з одним блоком без зображень), `results` ×5, **відео**-відгук, команда | найширший набір в IT-каталозі: компоненти з картинками, компоненти з лінком і компонент без медіа в одному записі; до того ж один із 4 кейсів із прапорцем ручної звірки (`orphanedI18nLink`) — показує, як методика поводиться з відкритим питанням |
| **`design/nastya-portrait-retouch`** | hero-сітка з 3 зображень, brief, `compare` (2 інтерактивні слайдери + 1 статична пара), `gallery` ×6 з лайтбоксом, `results` ×3, відео-відгук, команда | три різні форми «до/після» та галерея з підписами — саме те, з чого складається фотонапрям; найдовший набір підписів (title + caption на кожне порівняння) |
| **`video/cuprus-life`** | hero-сітка з 3 відео (постери, тривалість, формат, повноекранний плеєр), brief із власними заголовками, `results` ×2 колонки, **скріншот**-відгук із цитатою та аватаром, команда | відеонапрям: картки з постерами і бейджами, повноекранний плеєр, інший тип відгуку; плюс єдиний кейс, де цитата відгуку раніше була захардкоджена в JSX |

Разом три кейси вмикають **5 із 8 типів секцій** (`brief`, `featureList`,
`compare`, `gallery`, `results`), **усі 3 типи hero**, **обидва режими
`compare`**, **обидва наявні типи відгуку** (відео і скріншот; текстовий
тип підтримує схема, але в цих трьох записах його немає) і зовнішні лінки
всередині `featureList`. Не вмикаються `prose` і `links` — див. причину в
розділі 2; секційний `videoGrid` теж лишився поза цими трьома записами
(відеосітка Cuprus живе в hero).

### 10.1 `FullscreenVideo` — справжній діалог

**Відтворений дефект:** відкрити Cuprus → Shift+Tab із кнопки Close → фокус
переходив на фонову плитку.

- `role="dialog"` + `aria-modal="true"` + локалізована доступна назва
  `cases.ui.player` («Перегляд відео» / «Video player»).
- **Ізоляція фону:** кожен сусід ланцюжка предків діалогу отримує `inert` і
  `aria-hidden` — той самий обхід, що вже робить `ImageModal`; шапка, футер і
  решта сторінки стають недоступними для фокуса й для скрінрідера.
- **Пастка клавіатури:** Tab / Shift+Tab циклують у межах плеєра; фокус, що
  опинився поза діалогом, повертається всередину.
- **Блокування прокручування:** `document.body.style.overflow = "hidden"` на
  час відкриття.
- **Escape** закриває, фокус повертається на **плитку, що відкрила плеєр**.
  У WebKit клік не фокусує `<button>`, тому плитка передається явно
  (`onOpen(src, event.currentTarget)`) — не через `document.activeElement`.
- **Після закриття** відновлюються попередні `inert`/`aria-hidden`, значення
  `overflow` у `body` і попередній фокус.

Перевірки (`package4-case-check`, UA + EN, Chromium + WebKit): наявність
діалогу та локалізована назва → `inert` шапки/футера → блокування скролу →
початковий фокус → Shift+Tab / Tab / Tab усередині → Escape → відновлення
фону, скролу й фокуса → закриття локалізованою кнопкою.

### 10.2 Reduced motion у всіх нових компонентах

- `CaseHero` уже рендерився статично; тепер те саме роблять **картка brief**
  і **вкладені анімації `CaseFeatureList`** (підсадження скріншотів).
- Прибрано анімацію blur зі спільного блока: `cardVariants` більше не має
  `filter: blur(6px)` — ні спільна секція brief, ніщо інше в нових
  компонентах blur не анімує.
- `FadeIn`: у статичній гілці більше не губляться `data-*`/`aria-*` пропи
  (були мовчки відкидані), і обидві гілки позначені `data-reveal` — тест бачить

### 10.3 OG-зображення: фактичний формат і розміри

- `lib/seo.ts` задавав усім обкладинкам `width: 1200, height: 630,
  type: "image/jpeg"`. Тепер він **вимірює сам файл** (JPEG/PNG/WebP/GIF) і
  публікує фактичні `width`/`height`/`type`; якщо файл недосяжний або формат
  невідомий — ці необов'язкові поля **не декларуються взагалі**. Обкладинки
  не змінювалися.
- Додано перевірку, якої раніше не було: `checkOgImage()`
  (`scripts/lib/urlchecks.mjs`) + підключення в `check-urls.mjs`
  (повнота набору полів + звірка з реальним файлом) і контрольні кейси в
  `check-urls.selftest.mjs`. **Чинний PASS цю помилку не бачив** — він
  перевіряв лише наявність `og:image`.
- Фактичні значення: EVA `1536×1024 image/webp`,
  «Ретуш портретів» `800×1200 image/jpeg`, Cuprus `720×1280 image/jpeg`,
  головна `1200×630 image/jpeg`.
